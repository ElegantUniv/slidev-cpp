# C++ 프로그래밍 중간고사 — 채점 루브릭 (교수용)

> 각 문제는 **상 / 중 / 하** 3단계로 채점한다.  
> 0점은 무응답 또는 문제와 무관한 답변에 적용한다.

---

## 1번 (6점) — 메모리 구조

### 정답

| 항목 | 정답 | 근거 |
|------|------|------|
| (1) `g1 = 100` | **Data** | 초기화된 전역 변수 |
| (2) `g2` | **BSS** | 초기화되지 않은 전역 변수 |
| (3) `local` | **Stack** | 함수 내 지역 변수 |
| (4) `static int s` | **Data** | 초기화된 정적(static) 변수 |
| (5) `p` 자체 | **Stack** | 포인터 변수는 지역 변수 |
| (6) `*p` 공간 | **Heap** | `malloc`으로 동적 할당된 공간 |

### 채점 기준

| 수준 | 점수 | 기준 |
|------|------|------|
| 상 | 6점 | 6개 모두 정답 |
| 중 | 3점 | 3~5개 정답 |
| 하 | 1점 | 1~2개 정답 |

### 채점 포인트

- **(4) 함정**: `static int s = 0;`은 초기화된 정적 변수이므로 **Data**. BSS로 답하는 경우 오답.
- **(5)/(6) 함정**: 포인터 변수 `p` 자체는 Stack, `malloc`이 반환한 공간은 Heap. 둘 다 Heap으로 쓰면 (5) 감점.

## 2번 (6점) — 포인터 추적

### 정답

`p = arr + 2` → p는 arr[2](=30)를 가리킴

| 항목 | 정답 | 근거 |
|------|------|------|
| (1) `*p` | **30** | arr[2] |
| (2) `*(p + 1)` | **40** | arr[3] |
| (3) `p[-1]` | **20** | arr[1] (`p[-1]` = `*(p-1)`) |
| (4) `arr[2]` | **99** | `*p = 99` 이후 arr[2] 변경됨 |
| (5) `p[0]` | **99** | p[0] = *p = arr[2] = 99 |
| (6) `arr[1]+arr[3]` | **60** | 20 + 40 (arr[2]만 99로 바뀜) |

### 채점 기준

| 수준 | 점수 | 기준 |
|------|------|------|
| 상 | 6점 | 6개 모두 정답 |
| 중 | 3점 | 3~5개 정답 |
| 하 | 1점 | 1~2개 정답 |

### 채점 포인트

- **(3) 함정**: 음수 인덱스(`p[-1]`)가 유효함. 모른다면 오답.
- **(4)(5) 함정**: `*p = 99` 이후 arr[2]와 p[0]이 **함께** 99로 바뀜. (4)는 맞고 (5)를 30으로 답하면 오답.
- **(6) 함정**: arr[1](=20)과 arr[3](=40)은 변경되지 않음. arr[2]만 99.

## 3번 (6점) — 메모리 오류 분류

### 정답

| 항목 | 정답 | 근거 |
|------|------|------|
| (1) | **NULL 포인터 역참조** | `p = NULL` 설정 후 `*p` 접근 → Segfault |
| (2) | **정상** | `"ABC"` = 3바이트 + `'\0'` = 4바이트, `buf[4]`에 정확히 맞음 |
| (3) | **버퍼 오버플로우** | `malloc(3*sizeof(int))`는 인덱스 0~2만 유효, `arr[3]`은 범위 초과 |
| (4) | **이중 해제 (Double Free)** | `p`와 `q`가 같은 주소를 가리키므로 `free(p)` 후 `free(q)`는 같은 메모리를 두 번 해제 |

### 채점 기준

| 수준 | 점수 | 기준 |
|------|------|------|
| 상 | 6점 | 4개 모두 종류/정상 여부 정확히 기술 |
| 중 | 3점 | 2~3개 정확 기술 |
| 하 | 1점 | 1개 정확 기술 |

### 채점 포인트

- **(2) 함정**: (2)를 오류로 답하는 경우가 많음. `"ABC"`의 실제 바이트 수는 4(null 포함)이므로 **정상**이 정답.
- **(1)과 (3) 구분**: "댕글링 포인터"는 오답. (1)은 명시적으로 NULL을 역참조한 것이고 (3)은 경계를 벗어난 접근.
- **(4)**: `q = p`로 같은 주소를 복사한 점을 인식해야 이중 해제임을 알 수 있음.

## 4번 (6점) — 변수 scope와 값 전달

### 정답

| 항목 | 정답 | 근거 |
|------|------|------|
| (1) | **5 99** | `a`는 값 전달로 불변; `g`는 전역 변수이므로 변경됨 |
| (2) | **1** | static count 첫 번째 호출: 0 → 1 |
| (3) | **2** | static count 두 번째 호출: 1 → 2 |
| (4) | **3** | static count 세 번째 호출: 2 → 3 |

### 채점 기준

| 수준 | 점수 | 기준 |
|------|------|------|
| 상 | 6점 | (1)~(4) 모두 정답 |
| 중 | 3점 | (1)의 두 값 중 하나만 오답이거나, (2)~(4) 중 1~2개 오답 |
| 하 | 1점 | (1)에서 `a=99`로 오답 + 정적 변수 동작 미이해 |

### 채점 포인트

- **(1) 핵심**: `a`가 99로 바뀐다고 쓰면 **call-by-value 미이해**. `g`가 10으로 유지된다고 쓰면 **전역 변수 미이해**.
- **(2)~(4) 핵심**: static 변수는 함수가 종료되어도 값이 유지됨. 매 호출마다 0부터 시작하면 오답(1/1/1).

## 5번 (6점) — 참조(Reference) 추적

### 정답

| 항목 | 정답 | 근거 |
|------|------|------|
| (1) | **10 10** | `r`은 `a`의 별명 → 둘 다 10 |
| (2) | **20 20 20** | `r = b`는 `a = 20` (rebind 아님); `b`도 20 |
| (3) | **20 20 99** | `b = 99` 변경은 `a`(=`r`)에 영향 없음 |

### 채점 기준

| 수준 | 점수 | 기준 |
|------|------|------|
| 상 | 6점 | 3개 출력 모두 정답 |
| 중 | 3점 | (1)(3)은 맞으나 (2)를 `10 20 20`으로 답함 — rebind 오해이나 이후 논리는 일관됨 |
| 하 | 1점 | (1)만 정답이거나 전체적으로 포인터처럼 `r`을 해석 |

### 채점 포인트

- **(2) 핵심 함정**: `r = b`를 "r이 b를 가리키도록 rebind된다"고 오해하면 (2)를 `10 20 20`, (3)을 `10 20 99`로 답함. **중** 수준으로 채점.
- **(3) 연계**: (2)를 rebind로 오해한 경우 (3)에서 `a`가 20이 아닌 10으로 답하므로 논리 일관성 확인.

## 6번 (6점) — 참조 vs 포인터 비교표

### 정답

| 항목 | 정답 |
|------|------|
| (1) 참조 초기화 시점 | **선언 시 필수** (선언과 동시에 초기화 필요) |
| (2) 참조 null 가능 여부 | **불가** (null 참조 없음) |
| (3) 포인터 재지정 | **가능** (`p = &y` 등) |
| (4) 참조 값 접근 문법 | **`r`** (변수처럼 직접 사용, 역참조 불필요) |
| (5) 포인터 null 체크 | **필요** (null 역참조 시 UB) |
| (6) 참조 null 체크 | **불필요** (항상 유효한 객체를 가리킴이 보장됨) |

### 채점 기준

| 수준 | 점수 | 기준 |
|------|------|------|
| 상 | 6점 | 6개 모두 정확 |
| 중 | 3점 | 3~5개 정확 |
| 하 | 1점 | 1~2개 정확 |

### 채점 포인트

- **(1) 허용 표현**: "선언 시 반드시 초기화", "나중에 초기화 불가" 등 의미가 맞으면 정답.
- **(3)**: 구체적인 예시(`p = &y`)가 없어도 "가능"이라고만 써도 정답.
- **(5)(6) 대칭**: (5)는 필요, (6)은 불필요. 둘 다 "필요"로 쓰면 (6) 감점.

## 7번 (7점) — 생성자 / 소멸자 호출 순서

### 정답

```
생성 0          ← 전역 객체, main() 이전
생성 1          ← main() 진입
생성 2          ← func() 진입
생성 3
소멸 3          ← func() 종료 (생성 역순)
소멸 2
main 계속
소멸 1          ← main() 종료
소멸 0          ← 프로그램 종료 (전역 객체, 역순)
```

### 채점 기준

| 수준 | 점수 | 기준 |
|------|------|------|
| 상 | 7점 | 9줄 전체 순서 정확 |
| 중 | 3~4점 | 다음 중 하나만 오류: ① 전역 객체 생성/소멸 위치, ② func() 내 역순 소멸, ③ "main 계속" 위치 |
| 하 | 1점 | 생성 순서는 맞으나 소멸 전반 틀림, 또는 전역 객체를 완전히 누락 |

### 채점 포인트

- **전역 객체 함정**: `Res global(0)`은 `main()` 이전에 생성되고, 프로그램 종료 시 가장 마지막에 소멸됨. 누락하면 최대 중 수준.
- **소멸 역순 함정**: 같은 스코프에서 생성의 반대 순서로 소멸됨 (r3 → r2, main 후 r1 → global 순).
- **"main 계속" 위치**: `func()` 복귀 후, r1 소멸 전에 출력됨.

## 8번 (6점) — `const`와 포인터

### 정답

| 항목 | 정답 | 근거 |
|------|------|------|
| (1) `*p1 = 99` | **X** | `const int*` — 가리키는 값 수정 불가 |
| (2) `p1 = &b` | **O** | 포인터 자체는 const가 아니므로 재지정 가능 |
| (3) `*p2 = 99` | **O** | `int* const` — 가리키는 값은 수정 가능 |
| (4) `p2 = &b` | **X** | 포인터 자체가 const이므로 재지정 불가 |
| (5) `const int* const p3; *p3 = 1` | **X** | 둘 다 const이므로 값 수정 불가 |
| (6) `const int* p4; printf("%d", *p4)` | **O** | 읽기(역참조)는 허용 |

### 채점 기준

| 수준 | 점수 | 기준 |
|------|------|------|
| 상 | 6점 | 6개 모두 정답 |
| 중 | 3점 | 3~5개 정답 |
| 하 | 1점 | 1~2개 정답 |

### 채점 포인트

- **p1과 p2 혼동**: `const int*`(가리키는 값이 const)와 `int* const`(포인터 자체가 const)를 반대로 이해하는 경우, (1)~(4) 전부 오답 → 하 수준.
- **(5)**: 앞의 p1/p2 구분을 맞게 이해했다면 자연스럽게 X.

## 9번 (7점) — `enum class` 타입 안전성

### 정답

| 항목 | O/X | 이유 |
|------|-----|------|
| (1) `int n = RED` | **O** | C 스타일 `enum`은 `int`로 암묵적 변환 허용 |
| (2) `Color c = 2` | **X** | C++에서 `int` → `enum` 암묵적 변환 불가 |
| (3) `Direction d = NORTH` | **X** | `enum class`는 범위 한정(`Direction::NORTH`) 필수 |
| (4) `Direction d = Direction::NORTH` | **O** | 올바른 접근 방식 |
| (5) `if (RED == GREEN)` | **O** | `enum` 값은 `int`로 변환되어 비교 가능 |
| (6) `if (Direction::NORTH == Direction::EAST)` | **O** | 같은 `enum class` 타입끼리 비교 가능 |
| (7) `int n = static_cast<int>(Direction::EAST)` | **O** | 명시적 캐스팅은 허용 |

### 채점 기준

| 수준 | 점수 | 기준 |
|------|------|------|
| 상 | 7점 | O/X 모두 정답 + X 항목((2)(3)) 이유 정확 |
| 중 | 3~4점 | O/X 5~6개 정답, 이유 일부 불충분 또는 (1)(5) 오판 |
| 하 | 1~2점 | O/X 3개 이하 정답 |

### 채점 포인트

- **(1) 함정**: C 스타일 `enum`은 암묵적 `int` 변환이 **허용**됨. X로 쓰면 오답.
- **(5) 함정**: `RED`(=0)와 `GREEN`(=1) 은 정수로 비교됨. `enum class`가 아니므로 가능.
- **(2)(3) X 이유**: X 판정만 맞고 이유가 없거나 틀리면 각 0.5점 감점 적용 가능.

## 10번 (7점) — `new` / `delete`

### 정답

**(1)** (2점)

```cpp
// 오류: 배열은 delete[] 로 해제해야 함
delete[] arr;   // ← delete arr → delete[] arr 로 수정
```

**(2)** (2점)

정답: **b, c, d**
- `a` — `malloc`은 생성자 호출 안 함
- `b` — `new Foo` : 기본 생성자 호출
- `c` — `new Foo()` : 기본 생성자 호출 (b와 동일)
- `d` — `Foo f;` : 스택 할당, 기본 생성자 호출

**(3)** (3점)

모범 답안 (하나만 정확히 서술하면 정답):
> `new`/`delete`와 `malloc`/`free`는 내부 메모리 관리자(heap manager)가 다르며, `new`는 생성자/소멸자 호출과 타입 정보를 별도로 관리하기 때문에 혼용하면 Undefined Behavior가 발생한다.

### 채점 기준

| 수준 | 점수 | 기준 |
|------|------|------|
| 상 | 7점 | (1)~(3) 모두 정확 |
| 중 | 3~4점 | (1)(2) 정답, (3) 불완전(예: "같이 쓰면 안 된다"만 서술); 또는 (2)에서 2개만 선택 |
| 하 | 1~2점 | (1)만 정답, 또는 (2)에서 1개 이하 |

### 채점 포인트

- **(2)**: `b,c,d` 를 모두 선택해야 함. a만 빼고 맞으면 2점, 하나 더 틀리면 1점.
- **(1)**: `delete arr` → `delete[] arr` 수정을 정확히 써야 함. "delete[] 사용"만 쓰고 수정 코드 없으면 1점.

## 11번 (6점) — `std::string`

### 모범 답안

```cpp
#include <string>
#include <iostream>

std::string s = "Hello";
s += ", World";
std::cout << "길이: " << s.size() << "\n";   // s.length() 도 정답

if (s == "Hello, World")
    std::cout << "일치\n";

std::string sub = s.substr(0, 5);
std::cout << sub << "\n";
```

### 채점 기준

| 수준 | 점수 | 기준 |
|------|------|------|
| 상 | 6점 | 4가지 기능 모두 `std::string` API로 정확 구현, 컴파일 가능 |
| 중 | 3점 | 2~3가지 기능 정확 구현; 또는 구조는 맞으나 일부 API 오기(예: `s.len()`) |
| 하 | 1점 | `std::string` 선언만 하고 대부분 C 함수(`strlen`, `strcmp` 등) 사용 |

### 채점 포인트

- **허용 표현**: `s.size()` / `s.length()` 모두 정답. `std::cout` / `printf` 혼용도 허용 (기능이 맞으면).
- **부분 감점**: `substr(0, 5)` 인자 순서가 틀린 경우(예: `substr(5, 0)`) 해당 항목 0점.
- **C 잔재 감점**: `strcmp`, `strlen`, `strcpy` 등 C 함수 사용 시 해당 항목 0점.

## 12번 (9점) — 클래스 설계

### 모범 답안

```cpp
class Counter {
private:
    int count;
public:
    Counter(int init = 0) : count(init) {}

    Counter& increment() {
        count++;
        return *this;
    }

    Counter& reset() {
        count = 0;
        return *this;
    }

    int get() const {
        return count;
    }
};
```

### 세부 배점

| 요소 | 배점 | 기준 |
|------|------|------|
| `private` 멤버 변수 선언 | 1점 | `count`가 `private` 안에 있어야 함 |
| 생성자 + 초기화 리스트 | 2점 | `: count(init)` 형식 사용; 기본값 0 포함 시 1점 추가 |
| `increment()` + 체이닝 | 2점 | 증가 1점, `Counter& return *this;` 1점 |
| `reset()` + 체이닝 | 2점 | 초기화 1점, `Counter& return *this;` 1점 |
| `get() const` | 2점 | 반환값 1점, `const` 선언 1점 |

### 채점 기준

| 수준 | 점수 | 기준 |
|------|------|------|
| 상 | 9점 | 모든 요구사항 충족, 테스트 코드 정상 동작 |
| 중 | 4~5점 | 핵심 구조는 맞으나 다음 중 1~2가지 누락: 초기화 리스트, 메서드 체이닝(`return *this`), `get()`의 `const` |
| 하 | 1~2점 | 클래스 선언만 있고 메서드 대부분 미구현, 또는 `public`/`private` 구분 없음 |

### 채점 포인트

- **초기화 리스트**: 생성자 본문에서 `count = init;`으로 대입하면 초기화 리스트가 아니므로 해당 점수 미부여.
- **메서드 체이닝**: `return *this;` 없이 `return count;` 등을 쓰면 체이닝 불가 → 1점 감점.
- **`const` 누락**: `int get()` 으로 `const` 없으면 1점 감점. `const Counter` 객체에서 호출 불가.

## 13번 (6점) — 표준 입출력 버퍼링

### 정답

**(1)** (3점): **b, c**

| 보기 | 정답 | 이유 |
|------|------|------|
| a | 제외 | 터미널 → 라인 버퍼링 (`\n`마다 출력) |
| **b** | **포함** | 파일 연결 → 풀 버퍼링 |
| **c** | **포함** | 파이프 연결 → 풀 버퍼링 |
| d | 제외 | stdout은 여전히 터미널 → 라인 버퍼링 |

**(2)** (3점):
- `std::endl` = 개행(`\n`) + **버퍼 플러시(flush)** 즉시 수행
- `"\n"` = 개행만 수행 (flush 없음)
- 루프 1,000회 × `endl` = 1,000번의 시스템 콜 → 성능 저하; `"\n"` 사용 시 버퍼링으로 시스템 콜 최소화

### 채점 기준

| 수준 | 점수 | 기준 |
|------|------|------|
| 상 | 6점 | (1) b,c 정확 선택 + (2) flush 개념 및 성능 저하 이유 정확 서술 |
| 중 | 3점 | (1) 하나만 정답; 또는 (2)에서 기능 차이는 설명했으나 성능 이유 누락 |
| 하 | 1점 | (1) 오답(a,d 포함) + (2) 개념 혼동 |

### 채점 포인트

- **(1) 함정**: d는 `2> err.txt`로 stderr만 파일로 보내고 **stdout은 터미널에 유지**되므로 라인 버퍼링. 제외해야 함.
- **(2) 핵심 키워드**: "flush(플러시)", "시스템 콜" 또는 "버퍼 비움"이 포함되어야 상 수준.

## 14번 (7점) — `unique_ptr` 코드 추적

### 정답

```
생성 1
생성 2
블록 안
소멸 2
이동 후
p1은 nullptr
소멸 1
```

### 줄별 근거

| 출력 | 근거 |
|------|------|
| `생성 1` | `make_unique<Res>(1)` — 즉시 생성자 호출 |
| `생성 2` | `make_unique<Res>(2)` — 블록 진입 시 생성자 호출 |
| `블록 안` | `cout` 출력 |
| `소멸 2` | `}` 로 블록 종료 → p2 소멸 (unique_ptr 스코프 종료) |
| `이동 후` | `std::move(p1)` — 소유권 이전, 생성자/소멸자 호출 없음 |
| `p1은 nullptr` | `std::move` 후 p1은 `nullptr` |
| `소멸 1` | `return 0;` → p3 소멸 (소유권 이전된 Res(1) 해제) |

### 채점 기준

| 수준 | 점수 | 기준 |
|------|------|------|
| 상 | 7점 | 7줄 전체 순서 정확 |
| 중 | 3~4점 | 다음 중 하나만 오류: ① p2 블록 종료 시 즉시 소멸, ② `std::move` 후 p1이 `nullptr`, ③ 마지막에 `소멸 1`이 출력되는 위치 |
| 하 | 1~2점 | 생성 순서만 맞고 unique_ptr 소멸 시점 전반 틀림 |

### 채점 포인트

- **블록 소멸 함정**: 블록(`{}`) 종료 시 p2가 즉시 소멸됨. `return 0;` 시점에 소멸된다고 쓰면 오답.
- **`std::move` 함정**: `std::move`는 소유권만 이전하며 생성자/소멸자 호출 없음. 이 시점에 "소멸 1"이 출력된다고 쓰면 오답.
- **p1 nullptr 함정**: 소유권 이전 후 p1은 `nullptr` — 모르면 `p1은 nullptr` 출력 누락.

## 15번 (9점) — 종합: C → C++17 리팩토링

### 모범 답안

```cpp
#include <iostream>
#include <string>
#include <memory>

struct Student {
    std::string name;   // char name[32] → std::string
    int score;
};

void print_student(const Student& s) {   // Student* → const Student&
    std::cout << "이름: " << s.name << ", 점수: " << s.score << "\n";
}

void update_score(Student& s, int new_score) {   // Student* → Student&
    s.score = new_score;
}

int main() {
    auto p = std::make_unique<Student>();   // malloc → make_unique
    p->name  = "홍길동";
    p->score = 80;

    print_student(*p);
    update_score(*p, 95);
    print_student(*p);

    return 0;   // free 불필요 — unique_ptr 자동 해제
}
```

### 세부 배점

| 변환 요소 | 배점 | 기준 |
|-----------|------|------|
| `char name[32]` → `std::string` | 2점 | `std::string name;` 선언 + 대입문 (`strcpy` 제거) |
| `print_student` 참조 전달 | 2점 | `const Student&` 사용; `if(s==NULL)` 제거 |
| `update_score` 참조 전달 | 1점 | `Student&` 사용 |
| `malloc`/`free` → `make_unique` | 2점 | `make_unique<Student>()` + `free` 제거 |
| 전체 컴파일 가능 및 정상 동작 | 2점 | 위 4가지 변환 반영, 실행 결과 동일 |

### 채점 기준

| 수준 | 점수 | 기준 |
|------|------|------|
| 상 | 9점 | 4가지 변환 요소 모두 반영, 컴파일 가능, 원본과 동일하게 동작 |
| 중 | 4~5점 | 2~3가지 요소 변환; 예: `std::string` + 참조 전달 맞으나 `malloc`/`free` 그대로 남김 |
| 하 | 1~2점 | 1가지 요소만 변환, 또는 구조는 변환했으나 컴파일 불가 |

### 채점 포인트

- **`new`/`delete` 허용**: `make_unique` 대신 `new Student` / `delete p`를 사용해도 정답으로 인정.
- **`NULL` 체크 제거**: `if (s == NULL) return;` 삭제해야 함 — 참조는 null이 불가하므로 불필요. 남겨두면 컴파일 오류(`const Student&`는 NULL 비교 불가) → 0.5점 감점.
- **`printf` 혼용**: `std::cout` 대신 `printf`를 유지해도 기능이 맞으면 허용 (변환 요소가 아님).
- **`const&` vs `&`**: `print_student`에서 `Student&`(non-const)를 사용하면 1점 감점 (읽기 전용임에도 수정 가능성 열어둠).
